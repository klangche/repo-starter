TLDR: WHAT EACH FILE DOES (paths in a project, after setup)

FILES

AGENTS.md          Rules for AI. Only the owner edits it.
CLAUDE.md          Same as AGENTS.md. Some AI tools look for this name.
README.md          About the project: what it is, install, usage, features.
docs/SPEC.md       What the project builds: goal, stack, plan, task list.
docs/CODING.md     How code is written, in any language.
docs/ADOPT.md      How to start a project, or add the starter to an old one.
docs/PLANNER.md    Roles (Planner, Builder, Reviewer) and the work flow.
docs/BUILD.md      What to build. How to release. How to set up the repo.
docs/VERSIONS.md   List of all versions. The release step writes it.
docs/STATUS.md     Explains how work is tracked.
docs/TLDR.txt      This file.
docs/languages.csv All texts for users, with translations.
docs/READ_ME_FIRST.txt Goes inside the zip for users. Shows the install command.
.gitattributes     Git setting. Keeps both sides when two branches add rows.
.gitignore         Files Git should not track.

FOLDERS

changes/           One small file per change. Each pull request adds one.
status/            One small file per task. Shows who works on what.
template/          Only in the starter. Holds the project files.

ROBOTS (.github/workflows/)

check.yml           Checks every pull request against the rules.
pr-status.yml       Adds the label "ready" or "needs attention".
main-guard.yml      Warns if someone pushes to main without a pull request.
prepare-release.yml Makes the release pull request. You start it by hand.
release-zip.yml     Builds the zip and publishes it when you push a version tag.
